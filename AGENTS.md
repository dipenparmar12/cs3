## 1. What this is

- Port of Android **CloudStream 3** (Kotlin, 4.8.0) to a **Windows-first Electron desktop app**, keeping the community `.cs3` extension ecosystem working **without asking any maintainer to do anything**. That is why the JVM sidecar, the DEX→JVM translator and the android shim exist.
- Principle: Android defines expected behaviour; Electron defines delivery on desktop (`docs/PRD/00-index.md`).
- Upstream is **GPL-3.0**. `LICENSE` and `THIRD-PARTY-NOTICES.md` are at root and reachable from the packaged app via `settings/AboutPanel.tsx` (GPL §6). Bundled FFmpeg builds are GPL, not LGPL.

### 3.2 Test rules

- Pure decision logic gets a `*.test.mts` beside it, `node:assert/strict`, no framework.
- A regression test must be verified to **fail with the bug restored**. Say so in the report.
- Test the vacuous case: empty set, row with no members, first call.
- Impure tests are legitimate where the failure lives in the seam (real mpv, real ffmpeg). Mark slow; `--fast` skips them.
- Some `src/` tests fail under plain Node on type-only imports without an extension; `bun` resolves them. Bun 1.3.14 is installed and fine for scratch scripts (outside the repo).
- Never report "tested" for something you did not run. "Typechecks with `tsc -b`" is true; "tested" is not, unless you ran it.

### 3.3 Build traps

- **`tsc` in `bun run build` typechecks nothing.** Root `tsconfig.json` is solution-style (`"files": []` + references); plain `tsc` is a no-op. Use `tsc -b`.
- **Electron cannot launch in a headless cloud container.** Do not claim "I ran the app" unless you did.
- **`.ts` extensions on imports in `electron/media/` are load-bearing**: Node's type-stripping ESM loader will not resolve extensionless specifiers (`allowImportingTsExtensions` in both tsconfigs).
- **The preload is `dist-electron/preload.cjs`, CommonJS, and the window is sandboxed** (audit SEC-01). A sandboxed preload cannot be an ES module, and `"type": "module"` makes a `.js` one. The format is set on the preload's `build.lib` in `vite.config.ts` because the plugin overrides `output.format`. The preload may import only `electron` (`contextBridge`, `ipcRenderer`, `webUtils`).
- **Sidecar needs Java 21+** (class file 65). `SidecarSupervisor.resolveJava` checks `tools/toolchain/jdk-*` before PATH; a JAVA_HOME on 17 once broke everything silently. Maven lives in `tools/toolchain/apache-maven-3.9.16`, not on PATH.
- **Fresh clone order: sidecar → runtime-deps → bridge.** The sidecar produces the android shim the bridge compiles against; runtime-deps puts `library-jvm` in place. `library-jvm` and the bridge are vendored in `sidecar/runtime/`, so a fresh clone lacks only `sidecar/target/cs3-sidecar.jar` — the cause of the "Extension sidecar (cs3-sidecar.jar) is missing" report. `bun run setup`/`predev` builds it (~20 s).
- **`mvn package` on the sidecar rewrites the tracked `sidecar/runtime/cs3-sidecar-android-shim.jar`** (new timestamps, same classes). Do not commit it unless the shim changed.
- **"Install Required Components" can fetch Java and copy build outputs; it cannot build the sidecar or bridge.** `cs3/runtimeAdvice.ts` chooses the advice: Java only → the button; sidecar/bridge in a checkout → `bun run setup`; packaged app → reinstall. Never point a gap at a fix that cannot close it.
- **Bridge needs jitpack.io** (403s in some cloud sessions). Jars are vendored in `sidecar/runtime/`; `build-bridge.mjs` compiles against that directory with `kotlin-compiler-embeddable` from Central. Costs: the Kotlin compiler needs `kotlin-stdlib`, `reflect`, `script-runtime`, `daemon-embeddable`, `trove4j`, coroutines **and `annotations-13.0`** on its own classpath (codegen resolves `@Nullable` there); and the **previous** `cs3-provider-bridge.jar` must be excluded from the compile classpath, or sources compile against last build's copy of themselves.
- **`build-bridge.mjs` and Maven on Windows:** `spawnSync('mvn')` without `shell:true` will not resolve `mvn.cmd`. `findMaven()` tries platform spellings and prefers `tools/toolchain/apache-maven-*`.
- Cloud toolchain: Java 21, Maven, Bun, Node 22.
- **CI** (`.github/workflows/ci.yml`): version tags and manual `workflow_dispatch` only (to save quota during branch merges). Runs `tsc -b` and `bun run test --fast` on Windows and Linux. `release.yml` covers releases (§3.4). Neither runs `mvn test`, the slow suites or the e2e harnesses — those are yours to run.

### 3.4 Packaging — `bun run dist:win`

- Script: `tools/package/build-installer.mjs`. Order: preflight (`doctor.mjs --dist`: Node 20+, deps, JDK 21+, Maven, Windows `System32\tar.exe`) → `sidecar/pom.xml` → `runtime-deps` → bridge → `build-runtime.mjs --verify` → `build-media-runtime.mjs --verify` → `tsc -b` → `vite build` → `electron-builder --win nsis portable`.
- Variants: `dist:installer`, `dist:portable`, `dist:win:fast`, `dist:mac`, `dist:linux` (`--os` defaults to host; `--arch`, `--version`). `--skip-jvm` / `--skip-media` for UI iteration; both are flagged in the report.
- **Stages are incremental by default**, decided from files (2026-09-19). `upToDate(label, outputs, inputs)` skips a stage when every output exists and is newer than every input. `--clean` forces work; `--fast` skips the comparison and trusts disk (right for a fresh clone). The end of a run prints time per stage.
- Archives are cached in `/.cache/media-runtime/`, keyed by URL, gitignored (anchored). `--refresh` re-fetches (gyan.dev's `ffmpeg-release-essentials.zip` has a stable URL and changing contents). Downloads report progress every 2 s with a 10-minute deadline. A body shorter than `Content-Length` is rejected, not cached.
- `build-runtime.mjs` mirrors by difference and never wipes. A file is written only when size or mtime differs, so building does not need the app closed. A file that must be replaced while held reports which file and says to close CloudStream.
- Stalled mirrors: the cache is checked across every mirror before any is fetched. Deadlines: 20 s to start answering, and a watchdog firing only after 45 s with no bytes.
- `--quick` stores the payload uncompressed (packaging 336 s → 51 s; 898 MB instead of 240 MB). Right for a build you will run once; never for a release. The report says which was made.
- The jlinked JRE carries `cs3-link-stamp.json` (JDK home, major, module list). It is relinked only when that changes, or on `--relink`. The module list is in the stamp on purpose: a JRE linked without `jdk.crypto.ec` ships TLS that fails site by site.
- **Skipping a step fails silently.** `build-runtime.mjs` verifies what Maven produced rather than running Maven, so a package built without the sidecar step installs fine with zero extension capability. Verify `release/win-unpacked/resources/`: `media/` has ffmpeg, ffprobe, mpv; `sidecar/` has `cs3-sidecar.jar`, the jlinked JRE and 58 runtime jars.
- Measurements: 2026-08-29 `dist:win:fast` 158 s (setup 271.9 MB, portable 271.7 MB). 2026-09-19 `dist:portable` steady state 367 s (Maven ~0 s ×3 reused; sidecar/dist 2 s; media 8 s from archive cache; `tsc -b` 19 s; vite 3 s; electron-builder 336 s; portable 239.9 MB).
- Packaging trap table:

| Trap | Rule |
|---|---|
| electron-builder 26 rejects unknown config keys | Config lives in **`electron-builder.yml`**; no `build` field in `package.json` |
| `npmRebuild: false` | All native deps are N-API. **Set back to `true` if a non-N-API native dep is added** (then a C++ toolchain is needed) |
| A running `bun run dev` fails the package | `EPERM … rename win-unpacked.tmp` — Vite holds a dir handle. `vite.config.ts` ignores `release/`, `media-runtime/`, `dist-electron/` |
| `tar` on PATH ≠ the `tar` that reads 7z | mpv ships `.7z`; GNU tar cannot read it. Windows' `System32\tar.exe` (libarchive) is named explicitly |
| Fonts | Built CSS is grepped for `https://fonts.` before packaging. `grep -oE 'https://fonts[^)"]*' dist/assets/*.css` must find nothing |
| `shell: true` | Only where a `.cmd` shim needs it (cmd.exe splits unquoted paths on spaces) |

- **jlink module list is curated, not `ALL-MODULE-PATH`.** Critical: `jdk.crypto.ec` (ECDHE; else TLS fails site by site), `jdk.unsupported` (`sun.misc.Unsafe`, used by coroutines/OkHttp/Jackson), `jdk.localedata` (C-locale date parsing silently returns nothing for a multilingual corpus), `java.sql` (Jackson reflects `java.sql.Date`). Verify by running the corpus, not just building.
- **NSIS:** `oneClick: false`, `perMachine: false` (per-user, no UAC). Portable writes userData beside the exe. x64 only (ia32 cannot load webtorrent's native `.node`). **Signing comes from secrets only** (Microsoft Artifact Signing via `AZURE_*`, or `CSC_LINK`; Apple `APPLE_*` for notarisation). `tools/package/verify-signatures.mjs` checks final artifacts. An unsigned tag release is published only as an "(unsigned preview)" prerelease; `REQUIRE_SIGNING=true` makes that fail. **Never put `identity: null` in `electron-builder.yml`** (it disables signing even with a certificate). See `docs/release/distribution.md`. No `.ico` in repo.
- **macOS:** unsigned; `desktop/scripts/after-pack.cjs` ad-hoc signs every Mach-O under Resources first (`--deep` treats Resources as data, and the JRE lives there), then the bundle. Users clear Gatekeeper by hand. darwin-arm64 bundles no ffmpeg (no static build exists) and resolves Homebrew's. linux-arm64 has no uTP (`utp-native` ships no prebuild; webtorrent falls back to TCP).
- **Cross-platform release.** Pushing a `v*` tag runs `.github/workflows/release.yml`: version from tag (semver; stamped with `--version`, so `package.json` needs no bump; `workflow_dispatch` takes it as input and publishes nothing) → checks on 3 OSes (`tsc -b`, `test --fast`, `mvn test`) → build matrix: windows-x64 (`windows-latest`), macos-x64 (`macos-15-intel`; `macos-13` retired Dec 2025), macos-arm64 (`macos-14`), linux-x64 and linux-arm64 (`ubuntu-22.04` and `ubuntu-22.04-arm`, so glibc floor is 2.35) → per target `verify-package.mjs` and `smoke-package.mjs --installed` → publish job `verify-release.mjs` (all 13 packages, SBOM, signing records by name) → release created **as a draft**, uploaded, then published. **No partial releases.**
- Artifact names: `CS3-<v>-windows-x64-installer.exe` / `-portable.exe` / `-portable.zip`; `CS3-<v>-macos-<arch>.dmg` / `.zip`; `CS3-<v>-linux-<arch>.AppImage` / `.deb` / `.tar.gz`. ### 3.5 The runtime the app runs is not the one you just built

- `RuntimeProvisioner` copies sidecar and provider runtime into `%APPDATA%/<app>/cs3-runtime/` and resolves that copy **before** every build location. The most expensive trap in the repo: it once asked `findRuntimeDir()` where to copy *from* (answered with the app-managed copy first) and then skipped the copy as "already there". Installed apps kept the shim and bridge they shipped with. 5 of 8 failing extensions in one report were this bug alone.
- Rules: (1) the copy carries `runtime-stamp.json` (generation + fingerprint of every jar's name, size, mtime); `getStatus()` reports `stale` separately from `ready`. (2) Provisioning reads from **build locations only** (`findSourceComponents`) and picks **newest, not first**; `sidecar/dist/` is generated from `sidecar/runtime/` and goes stale when Maven runs again. (3) Translations drop when the sidecar changes; an absent stamp counts as changed.
- **Bump `RUNTIME_GENERATION`** whenever the shim, bridge or translator changes in a way an already-provisioned copy would get wrong. Currently **17** (one paragraph per generation in `runtimeProvisioner.ts`).
- Debugging "a class that should exist doesn't"? Compare `%APPDATA%/<app>/cs3-runtime/runtime/` with `sidecar/runtime/` first.

## 4. Architecture of `desktop`

```
RENDERER (React 19, src/)   App.tsx · views/{Home,Search,Detail,Library,Settings} · components/VideoPlayer …
        │ contextBridge, allow-listed, typed (electron/preload.ts)
MAIN PROCESS (electron/main.ts)  wires every service as a singleton; 361 ipcMain.handle calls
  ├─ Datastore           cs3_datastore.json in app.getPath('userData')
  ├─ ContentService      search → MetadataProvider → getSources → IndexerRegistry → startStream → TorrentEngine
  ├─ PluginManager       Sidecar Supervisor ──► JVM process (JSON-RPC over stdio) · WebView host
  ├─ TorrentEngine       WebTorrent + loopback HTTP server
  ├─ DownloadService     aria2c (RPC) / yt-dlp (portable binaries)
  └─ LibraryStore        watch state, resume, saved pages
```

- Shared types live in `src/types/{api,plugin,torrent,download,player,media,mpv}.ts` and are imported by both sides. This is intentional, not a layering mistake.
- Fallible handlers return an **envelope** `{ ok, error?, …payload }` and never reject, via `main.ts`'s `fail()`.

### 4.1 Four things change together

Crossing the boundary changes four places together: (1) the service in `electron/`, (2) `ipcMain.handle('ns:name', …)` in `main.ts`, (3) the method and type in `CloudStreamElectronAPI` in `preload.ts`, (4) the caller in `src/`. `electron/ipcSurface.test.mts` (`bun run test ipc`, runs first) pins every diff lexically and is mutation-verified in all three directions. Exceptions go in commented allow-lists with a reason; "I'll wire it later" is not a valid entry.

**`ipcRenderer.invoke` on an unregistered channel rejects — there is no `{ok:false}` envelope.** Seven channels were once strings that had stopped matching, invisible to `tsc`. `binary:setupBinaries` was invoked but never registered, so the first-run installer always failed, and `BinarySetupModal` caught the rejection and showed a reassuring notice. **A catch that reassures is worse than no catch.**

### 4.2 IPC surface

`electron/preload.ts` is the only bridge. `contextIsolation: true`, `nodeIntegration: false`. **361 invoke channels** (recounted 2026-10-20; was 349 on 2026-10-08) across the namespaces: `api: torrent: playback: search: indexer: sources: download: extension: library: datastore: binary: dialog: pages: natives: ott: issues: profiles: media: mpv: external: player: analytics: bookmarks: discover: subtitles: log: runtime: history: home: backup: network: ratings: metadata: regions: privacy: interactions: diagnostics: components: videos: window: app: shell: storage: userData: dev: userProfiles:`. `subscribe()` unifies 14 listener/teardown pairs; teardown prevents accumulation across React remounts.

| Channel group | Shape and rules |
|---|---|
| `playback:*` | **Push.** `playback:start` returns a session id at once; `playback:update` snapshots follow. The player renders from snapshots before a stream exists. `{ persistent }` (standard mode) walks every source and, once all fail, widens to every provider and indexer **once** by itself — the "Find more sources" press made for the viewer; snapshots carry `retryingElsewhere` and `tried`. A source the viewer picked is still the only one tried. `resumeKey` + `preferSource` (a stored source, e.g. from a bookmark) pin the resumed source first; snapshots carry `sourceStates` (played/failed per hash) for the picker's ✓/⚠. |
| played sources | `library:getPlayedSource(key, s, e)` / `forgetPlayedSource` + `library:updatePlayedSourcePreferences({title, year, season, episode, preferences})`. The audio/subtitle choice is stored on the played-source record, so Resume restores release and tracks together. Records carry provenance (provider, extension, repository) and the title the provider used. |
| `userData:*` | `summary` → erasable areas with counts and the `preserved` list; `erase(areaIds)` writes `backups/before-erase-<stamp>.json` first, then clears each area **through its owning store**, never its file. Infrastructure (mpv, ffmpeg, aria2, yt-dlp, JVM/sidecar, repositories, extensions, settings) is never an area — `cs3/userDataReset.ts`. |
| `dev:openInEditor(file, line, col, editor)` | UI inspector's "open source". Path resolved and **refused outside `app.getAppPath()`**; editors are an allow-listed scheme table (`vscode`, `cursor`, `windsurf`, `vscode-insiders`); anything else → `shell.openPath`. A packaged build has no sources and says so. |
| permissions | No IPC. `security/permissions.ts` is the session allowlist: the app's own origin gets clipboard-write, fullscreen and EME; nothing else, nobody else (Electron grants everything when no handler is set). The WebView partition refuses all permissions, downloads and popups. A feature needing a new permission adds it there, with the measurement. |

Fifteen providers are fifteen independent scrapes (Cinevood 20 s vs ARD 350 ms), so request/response would spend the whole time on a spinner. `api:searchAll` remains for callers needing a full answer. The fan-out uses one RPC per provider (`searchEach`), capped at 8 in flight. |

Whole state every time (`profiles`, `activeId`, `gated`). Under `ask`, `components/AdultSessionPrompt.tsx` asks once per launch, after any other dialog: Enable / Keep Adult Content Disabled, with "Do Not Ask Again" persisting `on`/`off`. Keyed on the title for everything about the work, on the address for everything about one source (`cs3/titleInteractions.ts`). |
| `videos:*` | `resolve(pageUrl)` turns a trailer's page into a stream. Returns a **provider-level, proxied** address, never a playable one: the renderer hands it to `media:prepare` like any other source. Separate from `metadata:*` because it spawns a process on a button press. |
| `external:*` | Drives a handed-off player and pushes `external:update` with a `capability` flag. Hand it the proxy's `capability.resolvedUrl` (provider headers applied), never the raw provider URL. `player:addCustom` (OS file picker in main; `validatePlayerPath`: absolute, exists, `.exe` on Windows; never `.bat` or `.cmd`) and `player:removeCustom` keep hand-added players (setting `external_player_custom_paths`). **No player is launched through a shell:** the OS default uses `rundll32 url.dll,FileProtocolHandler`, not `cmd /c start` (a URL's `&` once ran as a command). Every detached `spawn` has an `error` listener. |
| window pins | `window:set/getAlwaysOnTop` for the app window; `mpv:setOnTop` and `setVideoEnabled` for mpv's own window. |
| window fullscreen | `window:set/getFullScreen` + push `window:fullScreenChanged` (every transition, F11 and the View menu included). **The app has one fullscreen, the window's.** The player drives it (`src/utils/useWindowFullScreen.ts`), never the HTML Fullscreen API (the two stacked; a player minimised while HTML-fullscreen became a mini window on a black screen). The player releases only a fullscreen it took (on mini, hide, close). Esc that nothing consumed leaves fullscreen before it means Back. mpv keeps its own fullscreen. |
| `app:getStartupProfile` | **Read-shaped.** Returns this launch's stages, marks, stalls and the background queue. Developer mode is on the renderer side, but the channel is unconditional, so a reporter can answer "why is it slow" without turning developer mode on. |

- `metadata:*`: `getExtended`, `peekExtended`, `clearCache`, push `metadata:extendedUpdate`. Separate from `api:loadMedia` because it answers a different question at a different cost. `loadMedia` is what the app can **play**, and a Play press waits for it. `metadata:*` is what the title **is**, from four third-party catalogues, and nothing waits for it. Push-shaped because the record is emitted partial and refilled as each source lands. See "The cast list was a row of names" in `fn:metadata`.
- `ott:*` answers "can I watch Netflix?", keyed on the platform. `extension:*` is an inventory keyed on repositories and archives. OTT must answer even when the answer is no, so the list always contains every platform with how it is reachable.

## 5. Domain capsule — extensions, the sidecar and the android shim → `docs/agents/extensions.md`

**Mechanism.** A `.cs3` is a ZIP of Android DEX bytecode compiled against upstream's Kotlin provider API. `sidecar/` is a **separate JVM OS process** (not a thread), so a hanging plugin degrades to "unavailable" instead of taking the app down. `DexTranslator` converts DEX→JVM via dex2jar once at install, cached by SHA-256. `LinkageAnalyzer` assigns a tier `T1_DROPIN`…`T4_BLOCKED`. `PluginHost` reproduces Android's load sequence. Hand-written `android/**` stubs cover the platform classes providers reach for. Providers are addressed `cs3ext://<provider>/<handle>`.

**Modules.** `sidecar/` (Java) · `sidecar/bridge/` (Kotlin, supplies `:app` types) · `electron/pluginManager.ts` (repos, download, SHA-256, enable cascade) · `cs3/sidecarSupervisor.ts` (JSON-RPC over stdio) · `cs3/providerRegistry.ts` (what each archive registered) · `cs3/webViewHost.ts` (Cloudflare challenges) · `cs3/extensionIssues.ts` and `failureTaxonomy.ts` (diagnosis) · `cs3/nativeProviders/*` (compiled-in providers).

**Rules**
- Call `ensureProviderActive(name)` before using a provider. Loading is lazy and per archive, deduplicated by an in-flight map.
- Provider loading cannot be parallelised: providers self-register into a global, and overlapping loads steal each other's providers (measured: 176 mis-attributed).
- Bump `RUNTIME_GENERATION` whenever the shim, bridge or translator changes (currently **17**). The app runs a copy in `%APPDATA%`, not what you just built (§3.5).
- `cs3-provider-bridge.jar` must live in `sidecar/runtime/`, with the same loader as `library-jvm.jar`, or `BasePlugin` resolves as two different classes.
- **The sidecar's stdout carries RPC frames and nothing else.** A stray `println` desyncs the channel; logs go to stderr.
- **Shim rule: concede the type, refuse the operation.** Never widen a parameter or return type to `Object` (it renames the method; `ShimSignatureTest` enforces this). Never forge the package name. Never fake a platform number.
- `PluginHost.call` must catch `LinkageError`, not only `ReflectiveOperationException`: `Class.getMethod` resolves every public method's types, so one missing class kills a whole extension after it registered.
- A provider that works until you press Play → check `KotlinNameRepair` first (dex2jar corrupts Kotlin mangled names).
- **Never reintroduce a synthetic or placeholder source.** Empty result plus a reason, always.
- **The adult gate is `PluginManager.enabledProviderNames`**, the single funnel that search, scope, discovery, playback and downloads all pass through. It removes only **adult-only** providers (`NSFW` with no general type; `NSFW, Others` counts as adult-only). A **mixed** provider (9kMovies, Mp4Moviez: `Movie, TvSeries, NSFW`; 5 of 22 NSFW providers measured) stays available with adult off; its 18+ rows and explicit titles are screened instead (`src/utils/adultContent.ts`: `screenSections` and `screenLists` in `OttService` after the cache; `withoutAdultTitles` on search and recommendations). Upstream publishes no per-row flag (every title in 9kMovies' "18+ Movies" is typed `Movie`), so rows are classified from their own name, handle and titles; patterns are pinned against measured row names. With adult on, such rows are flagged `sensitive` and covered until the once-per-launch confirmation.
- **Built-in providers use `cs3native://`, never `cs3ext://`** (wrong-attribution failures).
- **Clearances are the host's, not the interceptor's** (`cs3/clearance.ts`, §5.15). Never keep `cf_clearance` per caller or re-solve without asking `clearance.get` first. Never relay (`clearance.fetch`) for a host the jar holds no clearance for.
- **The WebView host must finish before the sidecar stops waiting** (`cs3/hostDeadline.ts`). The reverse channel carries one deadline, and both ends used to spend it.
- **A failed `load()` closes its class loader, and `unload` withdraws what the plugin registered.** A leaked loader holds a Windows handle on the `.cs3`, and every later update fails its rename with `EPERM` (measured: Ultima, which fails at `load()` on every launch, could never be updated). `unload` removes the plugin's entries from `APIHolder.apis`, `allProviders` and `extractorApis` by `sourcePlugin`, as upstream's `unloadPlugin` does. `PluginUnloadTest` pins both and fails on the old code.
- **Installs and updates from the screen are background jobs** (`cs3/extensionJobs.ts`). Downloads overlap; everything after the verified download in `installPlugin` (rename, translate, load) runs through `PluginManager.oneAtATime`, because overlapping loads mis-attribute providers. Any new install path must go through `installPlugin` or take that lock.
- **Replacing an archive goes through `cs3/archivePlacement.ts`.** Retry the rename for ~1.5 s, then place the update beside the held file (`Name.hash.<sha12>.cs3`) and point the record at it. The held copy goes on `extension_displaced_archives` and is swept once released. Read an extension's archive from `record.filePath` (`archivePathFor`), never from the canonical path.
- **Extension updates install automatically by default, checked at most once per calendar day.** Android parity is in the default, not in the frequency (Android checks every launch; a desktop app restarted five times an evening would fetch every repository five times). Automatic installs are ordinary update jobs. See `fn:extensions` ("Extension updates: three reasons 'Update all' did nothing") and `extensions.md` §5.8.
- **Browse search** reaches into every repository's stored plugin list (`extension:peekRepository`, no fetch; `useCatalogListings`) and offers **Install all** for what matched (`catalogInstall.ts`, `CatalogInstallBar`). A repository the search names (name, shortcode, language), or the filters alone selected, offers everything. A description that merely mentions the word offers only matching extensions. Left out and counted: installed, already queued, maintainer-marked down (`status 0`), adult-only while adult is off, listed twice. Over 10 extensions, or any not-yet-read repository, is confirmed first. Never offered for the unfiltered catalogue.
- **Nothing installs until the viewer picks regions** (PRD-54, `cs3/regions.ts`). The first-run modal is pre-ticked from the locale; existing installs are asked once. Every matching verified repository is **added**. Starter extensions (≤16; working before beta before slow; nothing marked down; `starterPlugins.ts`) are **installed** from repositories matched through a named region (any language), and from **bundled** global ones (filtered to the selection's languages). Unbundled global repos are added only. Adult repos are added only when allowed and never installed from. **Cross-region** (default on, `cs3_content_regions_cross`): every unmatched non-adult repo is searched for plugins whose `language` is exactly a selected one (`strictLanguage`), and removed again if none are found. The region system only adds: an installed repository is skipped, so a manual off is never undone. Removal returns a list to review.
- The upstream jar lane exists, but only **1.9%** of the corpus publishes one. Do not plan work that assumes it.
- **Shims, measured:** `android.net.Uri` is implemented (RFC 3986; never validates, because `java.net.URI` throws on scraped URLs). `Handler` works (one executor per handler), and `Looper.getMainLooper()` is non-null. `Context.getSystemService` returns `null` (Android's contract). UI types throw `UnsupportedAndroidApiException` (demotes the tier, not a crash). `Intent` and `AlertDialog.Builder` build fine and refuse at `startActivity` and `show`.
- **A Kotlin companion is not inherited:** `CloudStreamApp.Companion` and `AcraApplication.Companion` each carry the methods; `PluginHost.invokeLoad` points both at the plugin's context before `load()`.
- `describeProvider` and `diffProviders` isolate per-provider failures: one unlistable provider must not discard the `ExtractorApi`s registered beside it.
- **Provider links are read, not guessed:** `ExtractorLinkType` and `isDash` come from the provider. Torrent and magnet links go to the torrent engine with `fileIndex` unset. A playlist is numbered rows (`part 2 of 3`), never one truncated row.
- **Platform-page search** is scoped by `SearchOptions.providers` through `SearchScopeStore.override` and is never persisted. `Disney+ Hotstar` → Hotstar and `JioHotstar` are pinned by name, not by declaration order.
- **Updates:** a same-version republish counts only from the extension's own repository (a mirror's hash describes a different build). Version bumps stay cross-repository. Download from the update's repository; install into the record's directory. "Update all" re-checks live, never the persisted snapshot.
- **A timeout is not a verdict:** `PluginManager.inspect` returns `null` for `TRANSPORT_ERROR_KINDS`, never `T4_BLOCKED` (which triggers an update rollback).
- **A repository added by address is the viewer's, not the app's** (`ProviderTreeRepository.userAdded`; no catalogue entry knows it). Stored in `installed_repositories_urls` (restored at launch; carried by the backup's `repositories` section; its on/off state by `extensionSwitches`). Bootstrap and catalogue updates only ever add bundled URLs, so they cannot overwrite or drop it. Its providers go through the same `enabledProviderNames` funnel as every other. Browse opens a repository in a right-hand drawer (`.ext-drawer`, about half the window, modal over a dimming backdrop `.ext-drawer-backdrop`; Esc or a backdrop press closes); the grid never moves. Actions are derived from state: Add only when not in the list; Install all or "Install N more" only while something is uninstalled; Remove only in the drawer and only when in the list; metadata folded under "About this repository"; search appears past six extensions. The Installed tree hides a disclosure whose level has one child; it shows the catalogue first and these below it under **Added by you**. An address reducing to a catalogued `owner/repo` (raw, project page or jsDelivr spelling) is the catalogue's and is never listed twice. Adding is **Installed → Add repository** (`AddRepositoryDialog.tsx`), never a URL bar in Browse.
- Provider origins are persisted (`cs3_provider_origins`), so a saved `cs3ext://` address can still say which extension owned it.
- Stremio `externalUrl` and `ytId` streams are dropped, not offered. A Jellyfin key bound to no user gives an empty `/Users`, reported as that, not as "no results".
- A cloud container's egress proxy 403s provider hosts (`net52.cc`…): the streaming half of a repository cannot be verified there. Never set `bundled: true` from a cloud run. `diagnostics` `mode: 'current'` selects by context and says so when it falls back to recent history.

## 6. Domain capsule — playback and the media engine → `docs/agents/media.md`

**Mechanism.** Chromium cannot decode much of what people stream: **AC-3, E-AC-3 and DTS return `""`**, and bare `video/x-matroska` reports `"maybe"` then drops audio silently; no HEVC without platform decoders. So playback is **inspect → decide → execute**. ffprobe produces `MediaMetadata`. A *pure* decision function turns metadata, renderer capabilities and host encoder into a `TransformationPlan`. The plan is executed as live fragmented MP4 on loopback, played natively, or handed to **mpv** (its own window, JSON IPC, hardware decode). `MediaProxy` serves everything from loopback because a browser cannot send the provider's `Referer`.

**Modules.** `media/mediaInspector.ts` · `media/decisionEngine.ts` (pure, tested) · `media/playbackEngine.ts` (the only source of a playable URL) · `media/mpvEngine.ts` and `mpvEmitPolicy.ts` · `mediaTranscoder.ts` · `mediaProxy.ts` · `media/inspectionStore.ts` · `subtitles/convert.ts` · `src/components/VideoPlayer.tsx` and `player/playbackRecovery.ts`.

**Rules**
- **`media:prepare` is the only source of a playable URL.** Assigning `video.src`, or handing mpv a link, from anything else reintroduces a fixed race. No channel returns an unclassified URL.
- **Nothing is decided from a URL string.** Transport comes from the first 64 KB of body (`#EXTM3U` or `<MPD`); codecs from the probe; DRM from the provider's declaration or the manifest.
- **`-c:v copy` never runs on unverified codec info.** Re-wrapping undecodable HEVC fails identically and looks like a different bug.
- Renderer capabilities are registered before playback (`App.tsx` → `media:setCapabilities`) and override the static table **in both directions**.
- **A track switch re-derives the plan** (`planForAudioTrack`). Never re-index an existing plan, or ffmpeg fails outright.
- **The software 4K guard is arithmetic, not a heuristic**: pixels per second, not height.
- **HDR re-encodes get the full `zscale` tone-map chain or none at all.** `tonemap` alone is measurably worse than nothing.
- **mpv:** hand it the **proxied** URL. Use `--no-config`, `--volume-max=100`, `--input-default-bindings=no` (defaults quit on `q`, which reads as "film ended"). Use `mpv.com`, not `.exe`. Wire it into `before-quit`.
- **Nothing reaches the main thread per frame or per chunk.** mpv snapshots are coalesced (`mpvEmitPolicy.ts`, 200 ms); proxy route eviction is scheduled, not per mint. Both were "not responding" freezes. An array or object field added to `MpvSnapshot` that only redraws (e.g. `bufferedRanges`) must go in `COALESCEABLE`: `!==` treats every fresh array as significant.
- **Probes are cached by origin URL; verdicts are always recomputed**, because a verdict depends on this machine's decoders.
- **A loopback URL returned from `wrap` is untouched**, or output is double-wrapped one hop per call.
- **PRD-40.1 status (2026-10-20):** `sourceLease.ts` is wired (`PlaybackEngine.prepare` → `MediaProxy.wrapLease`) **but cannot refresh: no resolver is supplied** (2026-10-21). `playbackTelemetry.ts` is built and tested but **not wired** (§6.11). Read §6.11 before touching either.
- **ClearKey:** payload decodable by the browser → `EME_NATIVE`; undecodable → ladder with `-decryption_keys`, **progressive only** (FFmpeg's DASH demuxer answers `Option decryption_key not found`, fatal to the whole command line). Encrypted DASH plays only through Shaka `DASH_NATIVE`.
- **The forced retry** in `PlaybackEngine.prepare` routes to `NATIVE_MPV` when available and policy is not `off` (not for `EME_NATIVE` or DRM), and rewrites the returned capability. Otherwise `VideoPlayer` hands the URL back to the element that just failed.
- **`MediaProxy`:** `Accept-Ranges` is stated, never forwarded. A 200 answering a mid-file range is refused. Never-served routes are evicted after served ones, newest first (`createdAt` vs `lastAccess`). Bodies are read as bytes and decoded only to sniff. The reader is cancelled, and upstream fetches carry an `AbortSignal` tied to the client socket. Tokens are 16 random bytes; a non-loopback `Host` is refused.
- **HLS audio can live inside the segments** (several AAC PIDs in each TS segment, no `#EXT-X-MEDIA`; Castle TV ships eng, hin, tam, tel). The manifest fast path alone invents one track. When no audio renditions are declared, the inspector reads the first segment's PAT/PMT (`media/tsProgram.ts`, 64 KB, ~0.7 s) and sets `audioMuxedInSegments`. hls.js plays only the first PID, so any other language is a **remux** (`REMUX_CONTAINER`, video and audio copied, `-map 0:a:N`), never the forced re-encode. Inspection cache entries carry `MEASUREMENT` (4), so older records (one track, no length, or a failed segment read stored as one language) are re-probed. **A segment read that fails is not a measurement:** the inspector retries once, then returns `segmentsUnread`; `PlaybackEngine` sets `languagesUnverified` on the capability and neither stores it in `InspectionStore` nor in its own cache, so the next prepare measures again (`playbackEngine.test.mts`, mutation-checked). The read has an 8 s deadline (`fetchBytes` in `main.ts`; it was 4 s) and logs `segment_streams_unread` (host only). A finished playlist states its length (`hlsPlaylistDuration`: Σ `#EXTINF` with `#EXT-X-ENDLIST`; a master takes its first variant's), the only length a converted HLS title has.
- **AAC copied into fMP4 gets `-bsf:a aac_adtstoasc`** when the plan's `copiedAudioCodec` is `aac`. ADTS from TS or HLS otherwise stops the muxer ("Malformed AAC bitstream", measured at 0.24 s). Only for AAC; the filter refuses other codecs.
- **ffmpeg's `-seekable 0` only for an origin the proxy saw ignore Range** (`MediaProxy.rangeSupportFor(url) === 'no'` → `createSession({ sequentialInput })`; ffprobe retries with it once, on a real 416). On every HTTP input it would cost `-reconnect` resuming mid-file, and moov-at-end MP4s.
- `wrap(url, headers, { boundedRanges: true })` is for hosts that refuse unbounded Range (YouTube DASH): first window 64 KB; total from `Content-Range`; status mirrors what was asked; a refused window is halved down to 64 KB.
- Never pass `--force-seekable` to mpv (a Range-ignoring origin makes it grind the whole file). Never pass `--untimed` in the matrix (it hides a stream that cannot hold realtime).
- **Volume has two writers.** Ignore incoming engine audio for `AUDIO_ECHO_MS` (700 ms) after a local change, and never send an engine's own level back (`engineAudio`, cleared when the engine changes). `clampVolume` on element and mpv: `video.volume` throws outside [0, 1].
- The native stage reports `onPausedChange` upward (element events never fire there). It does not forward buffering into `isBuffering`, which is a torrent's overlay.
- `build-media-runtime.mjs` fails the build on a missing required component (`--allow-missing` overrides). mpv is `required: false` off Windows on purpose (the distro package is wired to VA-API or VideoToolbox).
- A test origin on 127.0.0.1 is never proxied (`wrap` leaves loopback alone) and measures nothing. Verify a proxy regression test fails with the fix reverted. googleusercontent links expire (8 h signed, then `HTTP 400`); re-resolving is correct, not a bug.
- **A clip in place of the film is a source failure, not a playback success** (`src/utils/mediaSanity.ts`): expected runtime ≥ 20 min, stream < 6 min and < 15% of it → `onSourceUnplayable(reason)`, and the session moves on without a blocking dialog. Only after real playback started on *this* stream. Only a measured length is judged (`judgeableDuration`): a conversion by the inspection's `durationSeconds`, never the element's (what ffmpeg has muxed so far: 7.68 s one second in). A live hls.js playlist is not judged at all. Judging the element's duration skipped every converted Castle TV episode as "an 8 s clip", which was the whole of the 2026-10 "audio switch does nothing" report.
- **`PlaybackEngine`'s capability cache keys on what changes the verdict**: URL, headers, `preferredAudioLanguage` and `avoidNativeEngine`. Keyed on the URL alone, picking Hindi was answered in 2 ms with the English `HLS_NATIVE` verdict (`playbackEngine.test.mts`, mutation-checked).
- **A conversion is positioned in its request (`?t=`), never by `currentTime`**, because its output has no index. The initial prepare starts it at the carried or resume position (`conversionStart`). In-player re-prepares go through `attachAt` (conversion → `?t=`; mpv → `startSeconds` via `nativeStartAt`; element → carried seek on `loadedmetadata`). The resume effect waits for *this* stream's metadata (`metadataFor`): `duration` still held the previous source's when the session moved on. `blindFallbackPlan(host, audioIndex)` keeps the decided track ("Play in this window" and the forced retry once converted track 0).
- **Adult video is paused and hidden by privacy, on every engine** (`player/playbackPrivacy.ts` decides; `usePlaybackPrivacy.ts` applies). Verdicts: `open`, `protected` (adult, permitted, blurred or loading), `blocked` (adult off). The `<video>` is never remounted: it is paused, `play()` is refused on the instance until released, and the `player__video--protected` blur lands in the render the verdict changes. mpv drops its video track (`set vid no`: window closes, decoding stops). A protected open carries `startProtected` as per-file `pause=yes` and `vid=no`, so no frame is drawn. Play on a protected video reveals **that video only** (`revealAdultItem`); the click surface does not. Resume is owned: only a pause privacy made is undone, and only with the player in front. Media keys, the background policy and PiP (raw frames, no CSS) never reveal or resume. The OS media record is redacted. The panic key is `` ` `` (`Backquote`, `utils/emergencyBlur.ts`): blur only, ignored while typing. In mpv's own window it is a key binding that pauses and hides itself, then sends `cs3-protect`, which `main.ts` turns into `setAdultVisualBlurred(true)` without moving any window. Measured against real mpv (2026-10-16): key → pause ~55 ms; app path (pause plus drop video) ~20 ms. `vid` is not an observed property, so `selectedVideoId` stays `null`; ask `get_property vid`.

## 7–8. Domain capsule — torrents, indexers, search and ranking → `docs/agents/torrents-and-search.md`

**Mechanism.** Torrents run on WebTorrent with a loopback HTTP server doing range requests and sequential pieces, warmed at launch because the costs are cold-client costs (DHT bootstrap, info dictionary), never the swarm. Search fans out **8 providers at a time**, push-shaped via `search:update`, ordered by measured provider health. 19 built-in indexers each get a deadline derived from their own measured latency. Scope decides which sources a search may ask.

**Modules.** `torrent/torrentEngine.ts` · `torrentMetadata.ts` · `dhtNodeCache.ts` · `indexerRegistry.ts` and `indexers/*` · `indexerBudget.ts` · `botChallenge.ts` · `swarmHealth.ts` · `searchSession.ts` · `searchScope.ts` · `cs3/sourceScope.ts` · `cs3/searchOrder.ts` · `providerAnalytics.ts` and `providerRanking.ts` · `cs3/sourceProfiles.ts`.

**Rules**
- **A scope selection is a strict filter, not a preference.** An unresolvable selection is **reported**, never silently widened back to everything. Providers selected means exactly those, and no catalogues.
- **Discovery defaults to `origin` scope** (only the providers that produced the row), widening to `all` automatically when nothing is found. A failed escalation leaves the narrow answer standing. **A self-widened result is offered, never auto-started** (`playbackSession.discover`): it was found by title, and a title match can be a different work (errors audit 2026-10-050, Part 2 §4).
- **`searchOrder` falls back to the original order** if ranking returns anything that is not the same set. Silently searching fewer sources and calling it "no results" is the worst failure this app has.
- **`empty` ≠ `failure`.** An anime provider with nothing for *Dune* is correct.
- **An unscored failure is not recorded at all** (`UNSCORED_FAILURE_KINDS`). Recording it in `attempts` alone still moves the success rate.
- **Nothing is ever auto-disabled.** Auto-*enable* is opt-in and gated.
- **Indexer deadline = p90 of that indexer's own successes × 2.5, clamped to [4 s, 20 s].** Only successes shape it; otherwise timing out buys a longer deadline. Cooldown escalates; any success resets it.
- **A block or a rate limit never opens a browser.** Only a genuine challenge does. A Cloudflare challenge is routinely served as **HTTP 200**.
- **DHT: saved contacts go through `addNode()`, never `bootstrap`.** `dhtPort` is pinned to 6882.
- **All sources is a mode, not an erasure.** It must never throw away a saved selection.
- **Zero-pad episode terms** (`S01E02`). `S1E2` matches nothing and reads as "the indexer has nothing".
- **Ranking on a maintainer's `status`:** weight **0.4**, `minSamples` **0** (a declaration is not a sample). It loses to the counters as soon as they have anything to say.
- `sharedDiscovery.ts`: cancel by consensus (stop only when every caller has withdrawn). An aborted run is never joined. The prefetcher is the only caller passing `autoWiden: false`. The fan-out's `load(base)` may fail when `titleOverride` is known (enrichment only).
- `SourceCache`: removing the last source removes the entry (`hit: true` with nothing in it skips discovery). A 403 is never definitive (expiry or hotlink); 404 and 410 drop at once; three other failures drop.
- **Stremio addons:** an addon whose `idPrefixes` cannot address an id is skipped (it 500s), not counted as failing. Search is attempted whatever `extra` declares. Two deployments of one addon are two providers (the host is in the local id). A direct `url` stream gets `seeders: 1`, no `fileIdx`, and `directSourceIdentity` (shared with extensions).
- **yt-dlp** rows need audio **and** video (except manifests). `--no-playlist`. `resolve` answers with a reason. A pasted page URL becomes its own search row and is resolved when opened. Typing never triggers a page fetch.
- A prefix match is not charged for the untyped remainder. `SOURCE_PRECEDENCE`, not arrival order, decides which candidate names a merged work. `bun run test repositories` pins what the catalogue may claim; liveness is `survey-repositories.mjs`, run deliberately.
- More: `fn:search`.

## 9–11. Domain capsule — library, downloads, UI and lifecycle → `docs/agents/library-and-ui.md`

**Mechanism.** The library keys on `canonicalKey(title, year)` plus season and episode, never on a URL, so nothing is orphaned when an address dies. Every detail page opened is written down as a snapshot (display copy, provenance chain, every address known to reach the work), so a saved page never opens blank. Downloads are addressed by **source variant**, not title. The settings screen groups by subject and filters by *level*. All teardown happens on `before-quit`.

**Modules.** `cs3/libraryStore.ts` · `cs3/pageSnapshot.ts` and `src/utils/savedPage.ts` · `cs3/playedSource.ts` · `cs3/bookmarkStore.ts` · `downloadService.ts` and `aria2Engine.ts` · `download/resumePlan.ts` and `resumeWindow.ts` · `src/utils/downloadIdentity.ts` · `src/utils/resumePoint.ts` · `settings/settingsLevel.ts` · `cs3/backupService.ts`.

**Rules**
- **A links handle is not a page address** (`cs3/extensionAddress.ts`). `loadLinks` takes an opaque provider blob, often JSON; `load` takes a fetchable URL. Storing one as the other is how saved rows opened blank.
- **`recordProgress` keys on `canonicalKey` + season + episode, never `mediaUrl`.**
- **A library title keeps what discovery found for it.** `SourceCache.onWrite` → `LibraryStore.mergeDiscoveredSources`, matched on the page address or a linked episode address (`sourceAddresses`, set from the `sourceQuery` the detail page sends; a series is searched by each episode's own handle). Identity is provider + release + resolution (real infohash for torrents); 30 per title; `parsed` and `scoreReasons` dropped; never bumps `updatedAt`. A deliberate add with nothing cached runs one background discovery, under the "Load sources while you read" switch.
- **A null episode means "Play".** The resume rule is *furthest episode with history wins*, never most-recently-updated.
- **A later load may add and may correct, but may never blank.** Episode listings are all-or-nothing, never field-merged.
- **A download is identified by its variant**: media, season, episode, provider, release name, resolution, quality, language, audio. Never by title, and never by a synthesised per-URL `infoHash`.
- **A partial download must be proved to match before resuming.** One ranged 64 KB request answers range support, real length and byte identity together.
- **Completion is verified, not reported**: file exists, no `.part`, size within 1%.
- **`res.resume()` discards data but does not stop the transfer** (this has bitten three times). Destroy both request and response.
- **All teardown is on `before-quit`**, never `window-all-closed`. Any new service owning a socket, handle, timer or child process wires in there.
- **Escape is consumed in capture phase, only when it actually closed something**; otherwise closing a menu ends playback. On a details page an Escape nothing consumed is **Back** (`App.tsx`, beside Alt+← and mouse Back). It is skipped when `defaultPrevented`, in a text field, in fullscreen, with an `[aria-modal="true"]` or `.modal-overlay` open, or with the player in front. A new popover that listens on `window` in bubble phase must stop the key, or it closes **and** navigates.
- **Never name a `.tsx` and `.ts` alike but for casing.** One name on Windows; the wrong resolution blanked the whole window.
- **Reachability guards** exist for four things (channel invoked and registered, component mounted, module constructed; see §10 of the domain file).
- **Cards:** `visited` is a dimming, never a badge; failure always marked, success almost never; a failure the viewer disproved is retired. `Unsupported` is absence of evidence → `unknown`. Nothing tells a viewer an extension *will* work.
- **A privacy control is never held back** by mode or level. `ProviderRankingPanel`'s data and erase button stay in both. `advanced` means the *label* needs knowledge of how the app is built, not "rare". An unclassified row is basic.
- **PiP** only where it can work (`isPipSupported`: the element is what plays, `readyState`, the native engine is not holding the stream). The window pin unapplies itself on unmount. The `<video>` is never remounted in any mode.
- **aria2** reports `complete`, not `completed` (handle `removed` and `paused` too). Its port probes upward from 6800; success is claimed only once RPC answers.
- `PlayedSource` is recorded after 10 s of real playback, not on selection. A direct link with no recorded deadline counts as expired.
- **Every Resume outside the detail page goes through `App.handleResume(ResumeTarget)`**: Continue watching, Library, History, card Play buttons and saved-playback bookmarks. The detail page starts its session itself, with the same `resumeKey`. `handleResume` reads the played-source record for (key, season, episode) and starts the session with `resumeKey` and `preferSource`. An expired link is re-resolved through the **same provider** (`pickReplacement`, then `pickSibling`); only then does ordinary ranking take over. A pinned source that fails is dropped from the list, not retried.
- **Provenance is what played, never a catalogue.** History, Library and the player header name the provider, extension and repository of the active source (`originName.ts`). `Cinemeta` and `search://` are placeholders, not origins. The player's old "Refined from" line is gone: on a title reopened from the library, it printed some earlier session's search query.
- Bootstrap runs once (`BOOTSTRAP_VERSION`; a bump installs only what is new), caps at `PLUGINS_PER_REPOSITORY`, and never blocks.
- **Lifecycle:** shutdown is raced against 5 s and logs `shutdown_timeout` naming the pending service. A dropped file never navigates the window (`will-navigate`). DevTools is `Ctrl+Shift+I` only (F12 is the app's). Reload is gated on `!app.isPackaged`.
- **Metadata:** Wikidata `P161` + qualifier `P453` is performer and role as one fact. Commons images are always `?width=`; the raw URL never reaches the renderer. `assemble` source order is precedence (characters and photos first). Wikidata `P1651` is **not** a trailer. Trailer duration and date are not fetched. A field populated and never read is a defect (`backdropUrl` was drawn by nothing until `DetailHero`).
- More: `fn:ui`, `fn:metadata`.

## 12. Rules that cut across everything

- **Nothing is decided from a URL string.** Transport, codec, DRM and container all come from the body or the provider's own declaration. (Violated historically in `mediaInspector`, `ytdlpSources` and `providerLinks`; all fixed.)
- **A capability check ends in an allowlist, not a denylist.** `!UNSUPPORTED.has(x)` answers yes for everything it has never heard of, which is how an unknown codec was reported directly playable and then failed in the element (§6.16). Absent information is not the same as unrecognised information: no codec means "do not block"; a named unknown means "assume not". Same rule as `canPlayContainer`, which got it right first.
- **Files the app creates go through `storage/appStorage.ts`.** `cacheDir()` and `cacheFile()` for re-creatable data; `tempFile()` for a working file. Never `os.tmpdir()`, and never a path built from `userData` inside a feature. The exceptions are deliberate and commented: a Unix socket whose app-data path would exceed `sun_path` (mpv), and the unconfigured test fallback.
- **Third-party HTTP goes through `electron/torrent/http.ts`**, which swaps in Electron's `net.fetch` (honouring `app.configureHostResolver` and the system proxy). **Node's `fetch` honours neither.** Five call sites used global `fetch`, and the DNS-over-HTTPS setting silently did nothing for them. `externalPlayerControl` keeps global `fetch` deliberately (loopback VLC control; no DNS or proxy involved).
- **DNS defaults to `automatic` DoH (Cloudflare, Google) with system fallback** (`networkSettings.ts`); an explicit choice is kept. 2,454 `ERR_NAME_NOT_RESOLVED` for raw.githubusercontent.com in one install's logs: an ISP DNS block that stopped every repository fetch.
- **`net.fetch` runs with `referrerPolicy: 'unsafe-url'`** (`resilientFetch.primary` in `main.ts`). Under Chromium's default policy, a full-path `Referer` on a cross-site request is refused with `ERR_BLOCKED_BY_CLIENT`, not trimmed: 159 blocked requests in 36 logs (workers.dev and Hindmoviez 117; freecdn34 and NetMirror 37). aria2 never goes through Chromium, which is why those sources "downloaded but would not stream".
- **Timeout is not cancellation.** `AbortSignal.timeout()` gives `TimeoutError`; the caller's own controller gives `AbortError`. Conflating them scores a provider for the app's own decision to stop waiting.
- **Always `describeError`** (`src/utils/errors.ts`), never `x instanceof Error ? x.message : String(x)`. That idiom (82 copies across 37 files) collapsed every DNS, refused and TLS failure into `fetch failed`, and `groupingForm` then merged the network family into one row in the issue ledger. The real reason is in `error.cause`.
- **A GraphQL 200 can be a failure.** AniList returns bad-query, rate-limit and server-fault as **HTTP 200** with `errors` and null `data`, so `response.ok` was true and every caller rendered "no results". Check `errors`.
- **Byte formatters are parameters, not one function.** Release sizes use base **1000** (matching provider and tracker SI quotes); download progress uses base **1024** (matching the OS file manager). Deliberate; `format.test.mts` derives its expectations from the eight original implementations. Zero-placeholder differences are not deliberate: flagged, unresolved.
- **Stores return whole state, never deltas.** `disabledSet.ts` (which stores exceptions, so new extensions work by default), `profiles:*` and the scope trio must all agree, and rebuilding them from a delta is how they stop agreeing. **Bulk is the primitive.**
- **`util/disabledSet.ts` writes fields longhand**: `erasableSyntaxOnly` forbids constructor parameter properties.
- **The sidecar's stdout carries RPC frames and nothing else.** Plugin logs, JVM warnings and stack traces are forced to stderr. Keep it that way.
- **Never bundle main-process runtime deps.** `vite.config.ts` externalises `dependencies` and node builtins (bare and `node:` spellings). WebTorrent's native `.node` binaries (`node-datachannel`, `utp-native`) must also be `asarUnpack`-ed.
- **Every executable the app downloads goes through `FastChunkDownloader` with a verifiable source** (audit SEC-03): a publisher's own HTTPS origin, or `{ url, sha256 }`. A third-party mirror (ghproxy.net) without a pinned digest is dropped. A digest mismatch deletes the file. Never run a downloaded binary to "verify" it before its bytes are checked.
- **No shell strings for processes.** `spawn` or `execFile` with argument arrays. PowerShell takes paths through environment variables. (`cmd /c start <url>` ran `&…` as a command.)
- **Local files are served by `security/localFiles.ts`**: media and subtitles anywhere; anything else only inside the download folders; real paths, case-folded on Windows. Never add `userData` or `process.cwd()` back. Paths a renderer sends for writing (`targetFilePath`) are ignored; main builds them.
- **Nothing heavy runs at module scope.** Every `import` in `main.ts` is evaluated before `app.whenReady()` resolves, with no message pump running. That is exactly the interval Windows reports as "Not Responding". Measured before the fix: `webtorrent` 604 ms warm and **2,762 ms cold**; `cheerio` 242 and 1,740; `fast-xml-parser` 43 and 710; plus two `ffmpeg` child processes spawned from a top-level call (**4.65 s** cold). A third-party package reached only from a feature is an `await import()` behind that feature. A service is a `background.add(...)` task. `bun run test reachability` does not catch this; check the graph.
- **A store read at construction is read before the window exists.** `DiagnosticsLog` (5.53 MB), `PageSnapshotStore` (1.10 MB) and the datastore (7.10 MB) were 17.4 MB of synchronous read-and-parse before the first frame. Hydrate on first use, and have every entry point call the hydrator, including the write-only ones. Hydrating after a record was appended replaces the live state with the file's and loses it.
- **The datastore is debounced, coalesced and written atomically.** `save()` marks dirty; bytes land 250 ms later via temp file plus rename. It used to `writeFileSync(JSON.stringify(everything, null, 2))` on **every setter**: 7.1 MB, ~29 ms of main thread, for one `setBool`. Durability points call `flush()` or `flushSync()`: backup, import, rollback, `before-quit`.
- **Nothing asked once per card may parse a datastore value.** `datastore.getObject` is a `JSON.parse` on every call. Card states (`interactions:summarise`) peeked the source cache twice per poster, re-parsing its 1.94 MB each time: measured on a real install, 738 home cards took 14,681 ms of main thread (the "whole window freezes on Home and Search" report). Per-row read-only queries use a parse memoised on the stored string (`SourceCache.snapshot`, `LibraryStore.playedSnapshot`): 9.1 ms for the same screen. Paths that mutate still parse their own copy.
- **`spawn` is synchronous where it counts on Windows.** libuv calls `CreateProcessW` on the calling thread; a cold 87 MB ffmpeg costs ~590 ms there (5 ms warm). Never spawn a large binary from the main thread on a path nobody asked for. Short queries go through `media/toolCapabilities.ts`'s `runToolOffThread`; answers that only change with the binary are remembered against its path, size and mtime.
- **Controls come from `src/components/ui`** (`docs/agents/design-system.md`). No `<button style={{…}}>`, no new private button, input or switch class, no hand-built `position: fixed` dialog. A variant (`compact`, `ambient`, `destructive`…) is the way to change emphasis. What is still unmigrated is listed there; take an item with the next change to its file.
- **A catch that reassures is worse than no catch.**
- **Prefer an honest empty answer with a reason over a synthesised one.**
- **Viewer profiles are separated at the datastore, not in the UI.** A new per-person datastore key goes in `profiles/profileKeys.ts` and nowhere else. A new store that keeps a viewer's data in memory is built with `perProfile` on `datastore.forProfile(id)`. A per-person `localStorage` key goes through `profileStorage`. Work that writes per-person data from outside an IPC handler (an engine event, a download finishing) pins its profile with `runAsProfile`; `DownloadTask.profileId` is the example. Shared by design (documented, not leaked): downloads (files on disk), the source cache, page snapshots, provider analytics, incognito, the adult gate, extensions and network settings. **A backup carries the profile it was taken in**; the profile list (lock hashes) is non-transferable.
- **Viewer PIN and password (2026-10-20):** any length from 1 to 128 characters; no digit or format rule (a single letter is valid). Stored as salted scrypt. Masked by default in every PIN and password field, with an eye button to reveal (`SecretInput`). Do not reintroduce a minimum length or a 4-digit rule without a product decision.

## 14. Working agreements

- **Branching:** cloud and agent sessions develop on their assigned `claude/*` branch and push there. **Never push to `master`.** No PR unless asked.
- **Scope:** implement what was asked. Do not start on a PRD step because you read about it here.
- **Commits:** Conventional Commits, scope from the area (`feat(library):`, `fix(cs3):`, `feat(torrent):`, `feat(player):`, `docs:`, `chore(desktop):`).
- **Comments explain *why*, not *what*.** Match the surrounding density. No narration of the obvious.
- **TypeScript `strict`.** Avoid `any`. The existing ones are IPC plumbing, not precedent.
- **Report honestly.** "Typechecks with `tsc -b`" is true. "Tested" is not, unless you ran `mvn test` or exercised the path. GPL-3.0, third-party indexers and community plugins make overclaiming expensive.
- **Keep these files current.** Changing the IPC surface, adding a service, moving the sidecar contract, or finding a stale section: update it in the same commit. A new dated post-mortem goes in `fn:<area>`, never here. **Keep it dense**: facts, rules and measurements, not narrative. A post-mortem is worth one rule plus its number.
- **Do not vendor or commit:** `.cs3` archives, `library-jvm.jar`, `node_modules/`, `target/`, `dist/`, `dist-electron/`, downloaded `aria2c` or `yt-dlp` binaries. A `jar xf`'d sidecar jar is build output too. One branch merge carried 28 stray `.class` files beside their `.java` sources, and a stale compiled copy in the tree reads as a second, authoritative build.
- **Anchor every ignore rule that names a runtime directory.** A bare `extensions/` in `desktop/.gitignore` matched any depth, silently swallowing `src/components/extensions/`: the whole extensions screen vanished from every fresh clone and broke `tsc -b` unconditionally. Rules are anchored now (`/extensions/`, `/data/`, `/bin/`).
- **Scratch work** (benchmarks, one-off scripts) goes in the session scratchpad, not the repo.
- **Architecture review** before merge uses `.claude/skills/cs3-architecture-simplifier/SKILL.md`. Its output format: Context, Requirement coverage, Scores, Findings by severity, Simplification, Proposed design, File plan, Rewrite, Risk, Verification checklist, Decision.

### 14.1 Merging from `claude/refine` / `claude/android-media-desktop-dybtml`

`refine` forked at `881456a`, before this branch's streaming stack existed. It has no `providerLinks.ts`, `subtitles/convert.ts`, `clearKey`/`shakaSession`, `build-media-runtime.mjs`, or (because of the unanchored ignore rule) the extensions screen at all.

- **Cherry-pick additively; never take a whole-file rewrite from it.** That is why the 25-commit IPC refactor (`main.ts` → 24 `ipc/*` modules, `60da305`) was **not** merged: its `main.ts` predates this branch's 222-channel surface (written against 188), and it would delete modules it never knew existed. It can be re-derived as a template later, not cherry-picked.
- Rule: take features and refinements; leave anything touching playback behaviour, request headers or the native engine. This branch's proven streaming stack is the asset being protected.
- Not merged, each a behaviour change to a working path: `ext.to` gateway; mpv embedding (`mpvSurface.ts`); concurrent-open and end-of-playback `MpvEngine` changes; HEVC `hvc1` tagging; `unreadableSource`'s loopback-failure split; media-module logging-init changes.
- **Never take a prebuilt jar from a branch whose sources you have not compared.** `refine`'s `cs3-provider-bridge.jar` predates this branch's `:app` activity shims. Taking it for an unrelated fix would have silently regressed all of them: no compile error, no failing test, just extensions losing providers again.

### 14.2 A gap a missing-class count cannot see is not a gap that doesn't exist

The `WebViewResolver` stub (§5.9) resolved perfectly and did nothing, and four rounds of shim work never surfaced it. When auditing compatibility, "zero `NoClassDefFoundError`" is not "zero gaps". Compare against the Android source's *behaviour*, not just its type graph (`docs/roadmap/android-parity.md`).
