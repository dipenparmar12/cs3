# PRD-52: Private Streaming and Browsing

**Status:** Proposed  
**Scope:** Windows desktop application  
**Priority:** High  
**Primary objective:** Provide a reliable Incognito mode and privacy-preserving handling of adult and 18+ content without weakening normal search, streaming, downloading, repository, provider, or library functionality.

## 1. Product Summary

Implement a Chrome-style Incognito mode for the desktop application.

When Incognito is active, the application should continue to work normally for:

- Search
- Browse
- Repository and provider discovery
- Source resolution
- Streaming
- Playback
- Downloads
- Metadata/details
- Explicit bookmarks and library saves, when allowed

However, automatic activity generated by the private session must not be persisted to the normal user profile.

This includes:

- Search history
- Watch history
- Recently viewed state
- Continue Watching
- Playback progress
- Last played source
- Failed playback/title outcomes
- Provider performance analytics
- Personalisation signals
- Automatic source history
- Other automatically generated activity associated with the private session

The core architectural rule is:

> Privacy must be enforced at the main-process persistence boundary, not independently by every renderer component.

This provides a single source of truth and prevents future renderer code from accidentally persisting private activity.

Explicit user actions are different from automatic activity. If the user deliberately chooses to save something, such as adding a title to the library, bookmarking a page, exporting a link, sharing content, or starting a download, that action may persist according to the configured privacy settings.

## 2. Adult and 18+ Content Privacy

Adult and 18+ content requires an additional privacy guarantee because playback activity may be highly sensitive.

A user may explicitly enable access to adult or 18+ content. However, the application must not expose the user's consumption of this content through normal activity tracking.

### 2.1 Default behavior

Adult and 18+ playback activity must be private by default.

The application must not automatically persist:

- Adult or 18+ watch history
- Recently played adult or 18+ titles
- Continue Watching entries
- Playback progress
- Last played source
- Failed playback state
- Recommendations based on adult or 18+ activity
- Provider ranking signals generated from adult or 18+ playback
- Search history that identifies adult or 18+ titles
- Persistent activity indicators on cards
- Personalisation signals derived from adult or 18+ activity

This protection applies regardless of which repository, extension, provider, source, or streaming method supplies the content.

### 2.2 Incognito compatibility

Adult and 18+ content must work inside Incognito mode.

Incognito must not disable the user's ability to access content that they have explicitly enabled.

Incognito and the adult-content access gate are separate concepts:

- The adult-content gate controls whether adult or 18+ content can be accessed.
- Incognito controls whether activity is persisted.
- Enabling Incognito must not automatically enable adult content.
- Enabling adult content must not automatically enable Incognito.

### 2.3 Adult activity in normal mode

The application should provide a separate privacy setting that controls whether adult or 18+ activity may participate in normal activity tracking.

Default:

```text
Adult/18+ activity tracking: Disabled
```

If the user explicitly enables this setting, adult or 18+ activity may participate in the same activity systems as other content.

This setting must be clearly separated from the setting that grants access to adult or 18+ content.

### 2.4 Shared and family systems

The application must assume that multiple people may use the same Windows installation.

Adult or 18+ activity must therefore not be exposed to other users through:

- Shared history
- Library activity indicators
- Continue Watching
- Recommendations
- Recently viewed lists
- Search suggestions
- Provider ranking
- Analytics
- Persistent logs
- Synchronisation data
- Shared profile information

The privacy design must prevent sensitive activity from becoming visible through indirect signals.

### 2.5 Logging and diagnostics

Adult or 18+ content identifiers must not be written to persistent logs or diagnostics unless explicitly required for a privacy-safe technical purpose.

Developer or Advanced mode must not bypass these protections.

Live debugging may expose technical information necessary for troubleshooting, but durable diagnostic storage must remain privacy-safe.

## 3. Goals

### Primary goals

1. Provide a clear, trustworthy Incognito mode.
2. Prevent automatic private-session activity from entering persistent user data.
3. Keep streaming and source discovery fully functional in Incognito.
4. Allow explicit user actions to remain available.
5. Keep adult and 18+ activity private by default.
6. Apply privacy rules consistently across every repository and provider.
7. Enforce privacy in the main process so renderer code cannot bypass it accidentally.
8. Keep normal application behavior unchanged when Incognito is disabled.
9. Prevent private-session activity from influencing recommendations or provider ranking.
10. Clear volatile private-session state when the private session ends.

### Non-goals

This feature does not provide:

- Network anonymity
- VPN functionality
- DNS privacy
- Protection from ISP/network monitoring
- OS-level privacy
- Protection against Windows Recent Files
- Protection against disk-level media caches created by external applications
- Retroactive removal of activity that existed before Incognito was enabled
- A separate persistent user profile
- A second datastore
- A developer switch that disables the privacy guarantees

UI copy must describe Incognito as a persistence/privacy feature, not as network anonymity.

## 4. Privacy Model

The system has three distinct categories of data.

### 4.1 Persistent automatic activity

This data must be blocked while Incognito is active:

- History
- Progress
- Search history
- Source history
- Visits
- Failed title outcomes
- Provider analytics
- Personalisation signals

### 4.2 Session-only private state

This data may exist in memory while Incognito is active:

- Search results
- Search suggestions
- Temporary source cache
- Temporary page snapshots
- In-flight playback state
- In-flight source discovery
- Temporary provider results

It must be discarded when the private session ends.

### 4.3 Explicit user actions

These are deliberate actions and may remain persistent when the corresponding setting is enabled:

- Add to Library
- Remove from Library
- Bookmark
- Save page
- Save search results
- Start download
- Export
- Share
- Other explicit user-initiated saves

The application must clearly distinguish explicit actions from automatic activity.

## 5. PrivacyMode Service

Create a main-process service:

```text
cs3_windows/electron/cs3/privacyMode.ts
```

The service is the single source of truth for Incognito state.

### 5.1 State

```ts
interface IncognitoSettings {
  allowDownloads: boolean
  askBeforeDownload: boolean
  allowExplicitSaves: boolean
  rememberPreference: boolean
  clearSessionOnExit: boolean
}

interface PrivacyState {
  active: boolean
  settings: IncognitoSettings
}
```

Defaults:

```text
allowDownloads: true
askBeforeDownload: false
allowExplicitSaves: true
rememberPreference: false
clearSessionOnExit: true
```

The application should start with Incognito disabled unless the user explicitly enables the remember-preference option.

### 5.2 Service API

```ts
isActive(): boolean

setActive(active: boolean): PrivacyState

updateSettings(partial: Partial<IncognitoSettings>): PrivacyState

clearSession(): void
```

Rules:

- Every privacy-sensitive write must check the current main-process state at write time.
- Do not rely on cached renderer state for enforcement.
- Turning Incognito on starts a clean private session.
- Turning Incognito off ends the private session.
- Clearing the session removes volatile private data.
- The application must not create a second persistent datastore for Incognito.

## 6. Persistence Rules

The Incognito active state may only be persisted when:

```text
rememberPreference = true
```

When the preference is disabled:

- Incognito must start disabled after application restart.
- The active state must not remain persistent.
- Private session data must not survive the application process.

Settings may remain persistent because they are configuration, not activity.

Suggested datastore keys:

```text
incognito_allow_downloads_Bool
incognito_ask_download_Bool
incognito_allow_saves_Bool
incognito_remember_Bool
incognito_clear_on_exit_Bool
incognito_active_Bool
```

The active-state key should only be written when the remember preference is enabled.

## 7. IPC Contract

Create a `privacy:*` IPC namespace.

| Channel                  | Type   | Purpose                                          |
| ------------------------ | ------ | ------------------------------------------------ |
| `privacy:getState`       | invoke | Return the complete privacy state                |
| `privacy:setActive`      | invoke | Enable or disable Incognito                      |
| `privacy:updateSettings` | invoke | Update privacy settings                          |
| `privacy:changed`        | push   | Notify renderer components of the complete state |

The returned state must always contain:

```text
active
settings
```

Do not implement delta-only state updates.

Update together:

- `electron/main.ts`
- `electron/preload.ts`
- `src/types/api.ts`
- IPC surface tests

## 8. Automatic Activity That Must Be Blocked

### 8.1 Watch history

Gate:

```text
HistoryStore.record()
```

When Incognito is active:

```text
record() -> no-op
```

This covers:

- Detail page visits recorded as history
- Playback events
- Download-related history events
- Other callers using the same funnel

### 8.2 Playback progress

Gate:

```text
LibraryStore.recordProgress()
```

No playback progress should be persisted during Incognito.

This means:

- No Continue Watching entry
- No private resume position
- No private playback progress after the session ends

### 8.3 Last played source

Gate:

```text
LibraryStore.recordPlayedSource()
LibraryStore.markPlayedSourceUnavailable()
```

No provider/source preference learned during Incognito should leak into normal mode.

### 8.4 Search history

Gate:

```text
SearchHistoryStore.record()
SearchHistoryStore.setResultCount()
```

Private searches must not appear as newly created search-history entries.

Existing history from before Incognito may remain visible after returning to normal mode.

### 8.5 Failed playback and title outcomes

Gate:

```text
api:recordTitleOutcome
```

Private playback failures must not create persistent dead-row state or failure badges in normal mode.

### 8.6 Recently viewed state

Gate:

```text
interactions:visit
```

Private visits must not create persistent visited/dimmed card state.

### 8.7 Provider analytics and ranking

Gate:

```text
ProviderAnalytics.observe()
```

Provider performance observed during Incognito must not influence:

- Provider ranking
- Source ranking
- Recommendations
- Personalised discovery
- Future provider ordering

Analytics flush operations may continue to run, but they must contain no private-session activity.

## 9. Source Cache and Private Source Discovery

Streaming must remain fully functional during Incognito.

Private source discovery needs temporary caching so the user does not repeatedly search the same providers during one session.

### 9.1 SourceCache

Add:

```ts
setVolatileMode(active: boolean)
```

When volatile mode is active:

- Persistent source cache may be read where appropriate.
- New source writes go to memory.
- Source failures and successes stay in memory.
- `onWrite` must not persist private activity into the library.
- The volatile cache is discarded when the private session ends.

The following must continue working inside the session:

- Source reuse
- Source refresh
- Source expiry handling
- Shared discovery
- Provider retry logic
- Play-after-prefetch
- Failure suppression

### 9.2 Important privacy rule

A private source discovery must not silently update the persistent source cache or provider ranking.

## 10. Page Snapshots and Explicit Save

Page snapshots may be required to support an explicit Save Page action.

Therefore:

- Automatic page capture may happen in memory during Incognito.
- Private snapshots must not be persisted automatically.
- When the user explicitly chooses Save Page, the current volatile snapshot may be promoted to persistent storage if explicit saves are enabled.
- If explicit saves are disabled, the action must be rejected clearly.

Add:

```ts
promote(address)
```

to the page snapshot store.

This keeps automatic capture private while allowing an explicit save to work correctly.

## 11. Downloads

Downloads are explicit user actions and must continue to work in Incognito unless disabled in Privacy settings.

### 11.1 Default

```text
Allow downloads during Incognito: true
```

### 11.2 Download behavior

When a download starts during Incognito:

- The download must continue normally.
- The downloaded file remains available after Incognito ends.
- The download must not create normal watch/download history.
- Private metadata must not be persisted unnecessarily.
- The queue must not permanently expose that the download originated in Incognito.

### 11.3 Session cleanup

When the private session ends:

- Completed private download history rows are removed from the private UI.
- Downloaded files are never deleted automatically.
- Active downloads continue running.
- Queued downloads continue unless the user explicitly cancels them.

### 11.4 Download confirmation

Optional setting:

```text
Ask before starting a download in Incognito
```

Default:

```text
false
```

If downloads are disabled, this option is disabled.

## 12. Logging and Diagnostics

Privacy protection must also cover durable technical logs.

### 12.1 Application logger

For Incognito sessions:

- Continue recording technical runtime failures where required.
- Redact titles, search queries, URLs and other user activity identifiers.
- Do not persist sensitive media identity unnecessarily.

Use the existing redaction mechanism.

### 12.2 Diagnostics

Diagnostics that normally contain:

- Titles
- URLs
- Playback details
- Source information

must be gated or redacted during Incognito.

Extension-load failures that contain no user activity may continue to be recorded.

### 12.3 Developer mode

Developer or Advanced mode must not disable Incognito privacy guarantees.

Do not add a setting such as:

```text
Keep Incognito logs for debugging
```

Use live debugging instead.

## 14. Privacy Settings

Add a Privacy tab to Settings.

All privacy controls are basic user-facing settings and must remain visible outside Developer mode.

### Settings

1. Private browsing
2. Clear private session when exiting Incognito
3. Allow downloads during private sessions
4. Ask before starting a download in Incognito
5. Allow bookmarks and library saves in Incognito
6. Remember Incognito between launches
7. Keep adult/18+ activity out of normal history and personalisation
8. Adult/18+ activity tracking in normal mode, default off

Each setting should have a short explanation of its consequence.

Example:

```text

```

## 15. Adult and 18+ Content Access

The application should use a separate explicit access control for adult and 18+ content.

Requirements:

- Disabled by default.
- Requires explicit user consent.
- Does not automatically enable Incognito.
- Does not automatically change normal search behavior.
- Works with every supported repository and provider.
- Works in Incognito.
- Does not weaken privacy protections.
- Must not leak adult-content activity into normal profile state.

The adult access state may remain session-scoped according to the existing adult-unlock design.

## 16. Repository and Provider Compatibility

Privacy behavior must be repository-independent.

It must work consistently for:

- Bundled repositories
- Custom repositories
- Android-compatible repositories
- External providers
- Torrent providers
- Direct-link providers
- Metadata providers
- Source aggregators

No repository or provider should be able to bypass the application privacy boundary.

The application must continue to:

- Search active repositories
- Resolve providers
- Refresh expired sources
- Play streams
- Download content
- Retry failed sources
- Switch providers
- Switch quality/language/audio/subtitle sources

while Incognito is active.

## 17. Profiles

Incognito is not a separate persistent profile.

Rules:

- Incognito is temporary.
- It is global to the running application session.
- Switching profiles does not create a second privacy implementation.
- Private activity must not leak between profiles.
- No second datastore should be introduced.

## 18. Session Lifecycle

### Start Incognito

When enabled:

1. Set the main-process privacy state.
2. Start a clean private session.
3. Enable volatile source cache.
4. Enable private page snapshot capture.
5. Enable private log redaction.
6. Notify all renderer components.
7. Update navbar, search, player and settings indicators.

### During Incognito

All automatic persistence gates must remain active.

### End Incognito

When disabled:

1. Stop private persistence.
2. Clear volatile source state.
3. Clear volatile page snapshots.
4. Clear private suggestions and temporary caches.
5. Keep explicit saved data.
6. Resume normal persistence for future activity.
7. Notify all renderer components.

### Application exit

If:

```text
clearSessionOnExit = true
```

clear private session state before application shutdown.

Volatile memory must disappear regardless of shutdown behavior.

## 19. Edge Cases

| Scenario                                        | Expected behavior                                                                  |
| ----------------------------------------------- | ---------------------------------------------------------------------------------- |
| Enable Incognito during playback                | Future automatic writes are suppressed                                             |
| Disable Incognito during playback               | Future normal writes resume                                                        |
| Crash while Incognito                           | Private volatile state is lost and no automatic private state should exist on disk |
| Explicit bookmark in Incognito                  | Persists if explicit saves are allowed                                             |
| Add to Library in Incognito                     | Persists if explicit saves are allowed                                             |
| Download in Incognito                           | Download continues and file remains                                                |
| Disable Incognito while download is active      | Download continues                                                                 |
| Adult content in Incognito                      | Plays normally but activity remains private                                        |
| Adult content in normal mode                    | Activity remains private by default                                                |
| User explicitly enables adult activity tracking | Adult activity may participate in normal tracking                                  |
| Switch profile while Incognito                  | Privacy remains active                                                             |
| Restart with remember preference off            | Incognito starts disabled                                                          |
| Restart with remember preference on             | Incognito starts according to saved preference                                     |
| Existing normal history                         | Remains available after returning to normal mode                                   |
| Private source failure                          | Does not create permanent failure state                                            |
| Private provider success                        | Does not improve persistent provider ranking                                       |
| Private search                                  | Does not create new search-history entries                                         |
| Private playback progress                       | Does not create Continue Watching                                                  |
| Private recommendation signal                   | Must not affect future recommendations                                             |

## 24. Architectural Principles

### Privacy by construction

Do not depend on individual UI components remembering to suppress writes.

### Gate writes at the persistence boundary

A single main-process gate should protect each persistence funnel.

### Explicit actions are different from automatic activity

Do not disable deliberate user actions simply because they occur during Incognito.

### Private state should remain volatile

If private information does not need to survive the session, keep it in memory.

### Privacy must not break streaming

Incognito must change persistence behavior, not source discovery, playback, codec handling, proxying, downloading, or provider compatibility.

### Privacy must be repository-independent

No provider, extension, repository, or external source should bypass the application's privacy model.

### Adult privacy must be stronger by default

Adult and 18+ activity must remain outside normal activity tracking unless the user explicitly chooses otherwise.

### Do not overpromise

Incognito protects application persistence and activity exposure. It does not make network traffic anonymous or prevent OS-level traces outside the application's control.
